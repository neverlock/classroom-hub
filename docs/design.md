# Classroom Hub — Design

เว็บเก็บการบ้าน/งานค้าง/สิ่งที่เรียนของนักเรียนหลายห้อง เน้นความเรียบง่าย
ใช้งานภายในห้องเรียน (เว็บปิด) ผู้ปกครองและนักเรียนเปิดดูได้โดยไม่ต้อง login

สถานะ: ร่างออกแบบ (ยังไม่มีโค้ด)

## 1. เป้าหมายและหลักการ

- Login จริงเฉพาะ admin เท่านั้น นักเรียน/ผู้ปกครองไม่ต้องมี account
- นักเรียนโพสต์โดยกรอก **รหัสนักเรียน** อย่างเดียว UI แสดงเป็น "เลขที่ N"
- ดูข้อมูลย้อนหลังได้
- ใช้ free tier ของ Cloudflare ให้ได้ยาวๆ
- **Mobile first ทั้งระบบ:** ออกแบบและเขียน CSS สำหรับมือถือก่อน (กรอบ 320–400px) แล้วค่อยขยายด้วย `min-width` สำหรับจอใหญ่ ปุ่มและช่องกรอกสูงอย่างน้อย 44–46px ตัวอักษรในช่องกรอก ≥16px (กัน iOS ซูมเอง) คอลัมน์เดียวเป็นค่าเริ่มต้น ไม่มีการเลื่อนซ้ายขวา ทดสอบที่ 320px เสมอ
- ทำน้อยที่สุดที่ใช้งานได้ ฟีเจอร์เสริมอยู่ในหัวข้อ "Future" และเปิดใช้ภายหลังได้โดยไม่ต้องรื้อโครงสร้าง

## 2. บทบาทและสิทธิ์

| บทบาท | ยืนยันตัวตน | ทำอะไรได้ |
|---|---|---|
| Super admin | Cloudflare Access (email) อยู่ใน env `SUPER_ADMINS` | สร้าง/ปิด class, ตั้ง class admin, ทำได้ทุกอย่าง |
| Class admin | **ชื่อผู้บันทึก + รหัสแอดมินห้อง** กรอกครั้งเดียว จำใน cookie (ไม่ต้อง login ทุกครั้ง) | บันทึก/แก้/ลบสิ่งที่เรียนและการบ้าน, จัดการวิชาและนักเรียน, ซ่อน/ลบข้อความของใครก็ได้ในห้อง |
| Member | **รหัส** (ชื่อที่ผู้ใช้เห็นคือ "รหัส" เฉยๆ ตรงกับรหัสนักเรียนในระบบ) กรอกในช่อง password จำใน cookie | สร้างและแก้ไข post ของตัวเอง, แนบรูป |
| ผู้เยี่ยมชม | ไม่ต้องทำอะไร | อ่านอย่างเดียว |

| การกระทำ | ผู้เยี่ยมชม | Member | Class admin | Super admin |
|---|:-:|:-:|:-:|:-:|
| อ่าน | ✓ | ✓ | ✓ | ✓ |
| สร้าง post | – | ✓ | ✓ | ✓ |
| แก้/ลบ post ตัวเอง | – | ✓ | ✓ | ✓ |
| แก้/ลบ/ซ่อน post คนอื่น | – | – | ✓ (ห้องตัวเอง) | ✓ |
| จัดการนักเรียน | – | – | ✓ | ✓ |
| สร้างห้อง / ตั้ง class admin | – | – | – | ✓ |

### ข้อสมมติเริ่มต้น (ยังเปลี่ยนได้)

- Member แก้ได้เฉพาะความคิดเห็น (comment) ของตัวเอง
- สิ่งที่เรียน/การบ้าน (`entries`) ลงโดย class admin เท่านั้น ส่วน member เขียนความคิดเห็น (`comments`) ใต้การ์ดแต่ละใบ แนบรูปหรือวางลิงก์ได้ ไม่มีส่วน "ข้อความจากเพื่อน" แยกในหน้าหลัก
- Class admin ใช้ "ชื่อ + รหัสแอดมินห้อง" แทน Cloudflare Access: รหัสเป็นความลับร่วมของแอดมินห้อง (เก็บเป็น hash) ชื่อที่กรอกใช้บันทึกว่าใครเป็นคนลง เปลี่ยนรหัสเมื่อไรทุกเครื่องต้องกรอกใหม่ (เก็บ `pin_version` ใน cookie) Super admin ยังใช้ Cloudflare Access
- อ่านได้ทุกคนโดยไม่ต้องกรอกอะไร
- รูป: ไม่เกิน 3 รูปต่อ post รับไฟล์ต้นฉบับขนาดเท่าไรก็ได้ แล้วย่อฝั่ง client ก่อนอัปโหลด (ดูหัวข้อ 5)

## 3. การยืนยันตัวตนของ member (ไม่มีรหัสห้อง)

เว็บเป็นเว็บปิดใช้ในห้อง จึง**ไม่ใช้รหัสห้อง** Member ระบุตัวตนด้วย "รหัส" เท่านั้น (ค่าเดียวกับรหัสนักเรียน แต่ UI เรียกสั้นๆ ว่า "รหัส")
ระบบนี้เป็นการ "ระบุตัวตน" ไม่ใช่การ "พิสูจน์ตัวตน" ใครรู้รหัสนักเรียนก็โพสต์แทนได้ จึงมีมาตรการรองรับแบบเบาๆ:

- เก็บ `student_id` และเวลาในทุก post เพื่อตรวจย้อนหลัง
- Class admin ซ่อน/ลบ post ได้
- ช่องกรอกรหัสเป็นชนิด password (ซ่อนตัวอักษร) จำใน cookie บนอุปกรณ์ เพื่อไม่ต้องกรอกซ้ำ หลังจำแล้วฟอร์มแสดง "โพสต์ในนาม เลขที่ N · ไม่ใช่ฉัน?" แทนช่องกรอก
- ตรวจรหัสนักเรียนกับตาราง `students` ของห้องนั้นเสมอ (รหัสที่ไม่มีในห้อง โพสต์ไม่ได้)
- Rate limit ต่อ IP / ต่อ student เพื่อกัน spam

## 4. คำแนะนำสำหรับอนาคต (ยังไม่ทำ)

เผื่อมีการปรับปรุงเมื่อใช้งานจริง ฟีเจอร์ด้านล่างออกแบบให้เปิดใช้เพิ่มได้โดยไม่ต้องรื้อระบบ

### 4.1 รหัสห้อง (class passcode)

ใช้เมื่อ: URL หลุดออกนอกห้อง หรือมีคนนอกเข้ามาอ่าน/โพสต์

- เพิ่มคอลัมน์ `classes.passcode_hash` (nullable) — `null` = ไม่ใช้รหัสห้อง
- Class admin ตั้ง/เปลี่ยน/ปิดรหัสได้เอง
- ผู้ใช้กรอกครั้งเดียวต่ออุปกรณ์ แล้วเก็บเป็น signed cookie (เช่น 30 วัน)
- เลือกขอบเขตได้ 2 แบบ: ต้องมีรหัสก่อน **โพสต์** (อ่านได้ฟรี) หรือก่อน **อ่านและโพสต์**
- เก็บเฉพาะ hash (เช่น PBKDF2/scrypt ผ่าน Web Crypto) ห้ามเก็บ plaintext

### 4.2 PIN รายบุคคล

ใช้เมื่อ: มีการแอบอ้างเลขที่ของเพื่อนจริง

- เพิ่ม `students.pin_hash` (nullable) PIN 4 หลัก ตั้งโดย class admin
- ตรวจ PIN ร่วมกับรหัสนักเรียนเมื่อโพสต์ พร้อมจำกัดจำนวนครั้งที่ลองผิด

### 4.3 อื่นๆ

- Turnstile (CAPTCHA ฟรีของ Cloudflare) หน้าฟอร์มโพสต์
- เก็บประวัติการแก้ไข post (`post_revisions`)
- `noindex` ทั้งเว็บเพื่อไม่ให้ search engine เก็บ
- Backup D1 เป็น SQL เป็นระยะ (cron/GitHub Action) ไปเก็บใน R2

## 5. รูปภาพ: ย่อก่อนเก็บ

ผู้ใช้เลือกรูปจากมือถือได้ทุกขนาด (หลาย MB ก็ได้) ระบบย่อให้เองก่อนอัปโหลด

**ทำฝั่ง browser ไม่ทำฝั่ง server** เพราะ Workers free tier มี CPU จำกัดมาก (~10ms ต่อ request) ย่อรูปบน Worker ไม่ไหว และการย่อก่อนส่งยังประหยัดเน็ตมือถือของผู้ใช้ด้วย

ขั้นตอน (ไม่ต้องใช้ library):

1. `createImageBitmap(file, { imageOrientation: 'from-image' })` — อ่านรูปและหมุนตาม EXIF ให้ถูกทิศ
2. คำนวณขนาดใหม่ให้ด้านยาวสุด ≤ **1600px** (รักษาสัดส่วน ไม่ขยายรูปที่เล็กกว่านั้น)
3. วาดลง canvas แล้ว `canvas.toBlob(..., 'image/webp', 0.8)` (fallback เป็น `image/jpeg` ถ้า browser ไม่รองรับ webp)
4. อัปโหลด blob ที่ได้ ปกติรูปจากมือถือ 3–8MB จะเหลือราว 150–400KB

ผลพลอยได้: การวาดใหม่ผ่าน canvas ตัด EXIF ทิ้ง ทำให้พิกัด GPS และข้อมูลกล้องไม่หลุดไปกับรูปเด็ก

กฎที่ยังต้องมี:

- Server จำกัดขนาดไฟล์**หลังย่อ**ที่ ~1MB ต่อรูป และตรวจ content-type (jpg/png/webp) เพราะฝั่ง client ถูกข้ามได้
- ถ้า browser ถอดรหัสรูปไม่ได้ (เช่น HEIC บางเครื่อง) ให้แจ้งผู้ใช้ให้เลือกรูปอื่น ไม่ต้องอัปไฟล์ดิบ
- จำกัด 3 รูปต่อ post
- ประมาณการ: 10GB ของ R2 free เก็บรูปราว 300KB ได้หลักหมื่นรูป เกินพอสำหรับห้องเรียน

## 6. Framework

**SvelteKit + `@sveltejs/adapter-cloudflare`**

เหตุผล:

- Bundle เล็ก เหมาะกับขีดจำกัดขนาด Worker ของ free tier (Next.js บน Cloudflare มักใหญ่กว่ามาก)
- เข้าถึง D1/R2 ผ่าน `platform.env` ได้ตรงๆ
- Form actions ทำงานได้แม้ไม่มี JS ฝั่ง client ทำให้ฟอร์มง่ายและเสถียร
- SSR ในตัว หน้าอ่านเปิดเร็วบนมือถือ
- Drizzle ORM รองรับ D1 และมี migration

ทางเลือกที่ไม่เลือก: Next.js (หนัก, ต้องผ่าน OpenNext), Hono ล้วน (เบาที่สุดแต่ต้องทำ UI/routing เอง)

**การอยู่ใน free limit:** Workers free ให้ ~100,000 requests ต่อวัน ส่วนไฟล์ static ไม่นับ ห้องเรียนเดียวใช้ไม่ถึงหลักพันต่อวัน แนะนำให้ cache หน้าอ่านสั้นๆ ที่ edge เพื่อลดการเรียก D1 อีกชั้น

Cloudflare แนะนำ Workers + static assets แทน Pages สำหรับโปรเจกต์ใหม่ ให้ตรวจเอกสารล่าสุดตอน scaffold

## 7. Deploy

Cloudflare ทั้งหมด:

| ส่วน | บริการ |
|---|---|
| Hosting / API | Workers (หรือ Pages) |
| ฐานข้อมูล | D1 (SQLite) |
| เก็บรูป | R2 |
| Login ของ admin | Cloudflare Access |
| CI/CD | GitHub → Cloudflare (auto deploy) |

โควตา free tier เปลี่ยนได้ ควรตรวจหน้า pricing ของ Cloudflare ก่อนใช้งานจริง

## 8. โครงสร้างข้อมูล

```
classes      id, slug (unique, ไม่เปลี่ยนตลอดอายุระบบ), admin_pin_hash, pin_version,
             current_term_id, active, created_at
terms        id, class_id, name (เช่น ภาคเรียนที่ 1/2027), class_label (ชื่อห้องในภาคเรียนนี้ เช่น ป.6/1),
             start_date, end_date                 -- ช่วงวันที่ของภาคเรียนห้ามทับกัน
subjects     id, class_id, code (เช่น ค21103), name, teacher (null ได้), sort_order, active
students     id, class_id, student_code, seat_no, active
                                                  -- unique(class_id, student_code)
entries      id, class_id, entry_date, subject_id,
             lesson,                              -- งานในคาบ / สิ่งที่เรียน
             has_homework, homework_detail, homework_due,
             author_name, hidden, hidden_by, hidden_at, created_at, updated_at
                                                  -- unique(class_id, entry_date, subject_id)
comments     id, entry_id, student_id, seat_no (snapshot ตอนโพสต์), body,
             hidden, hidden_by, hidden_at, created_at, updated_at
attachments  id, entry_id (null), comment_id (null), r2_key, size, created_at
```

- Super admin ไม่มีตาราง ใช้ env `SUPER_ADMINS=a@x.com,b@x.com`
- `entries` คือ 1 วิชาต่อ 1 วัน รวมสิ่งที่เรียนและการบ้านไว้ใน record เดียว (ตามระบบเดิม) ถ้าเลือกวัน+วิชาที่มีแล้ว ฟอร์มจะเปิดโหมดแก้ไขของเดิมแทนการสร้างซ้ำ
- **ภาคเรียน (terms):** `entries` ไม่มี `term_id` ใช้ช่วงวันที่ `entry_date` อยู่ใน `start_date`–`end_date` ของภาคเรียนเป็นตัวกำหนด จึงไม่ต้องย้ายข้อมูลเมื่อแก้ช่วงวัน หน้าหลักแสดงเฉพาะ**ภาคเรียนปัจจุบัน** (`classes.current_term_id` ที่แอดมินตั้งเอง ไม่เดาจากวันที่) ภาคเรียนอื่นดูย้อนหลังได้จากตัวเลือกภาคเรียน ไม่ปนในหน้าแรก
- **ระบบใช้ข้ามหลายปี:** ชื่อห้องอยู่ที่ `terms.class_label` ไม่ใช่ที่ `classes` เพราะปีหน้าห้องเปลี่ยนชื่อได้ (ป.5/1 → ป.6/1) หัวข้อของหน้าหลักใช้ชื่อห้องของภาคเรียนปัจจุบัน ส่วนตอนดูภาคเรียนเก่าแสดงชื่อห้องของภาคเรียนนั้น `slug` และ URL ไม่เปลี่ยนตลอด
- "การบ้านที่ต้องส่ง" = `entries` **ในภาคเรียนที่ดูอยู่** ที่ `has_homework` และ `homework_due >= วันนี้` เรียงตามกำหนดส่ง (ซ่อนส่วนนี้เมื่อดูภาคเรียนเก่า)
- "งานเลยกำหนดส่ง" = `entries` ในภาคเรียนที่ดูอยู่ ที่ `has_homework` และ `homework_due < วันนี้` จัดกลุ่มตามเดือนของ `homework_due` (เดือนใหม่สุดก่อน) ไม่ต้องมีสถานะ "ส่งแล้ว" เพิ่ม ใช้วันที่ตัดสินอย่างเดียว
- วันที่แสดงเป็น ค.ศ. รูปแบบ `dd/mm/yyyy` เหมือนระบบเดิม ชื่อเดือนในหัวกลุ่มเป็นภาษาไทย + ปี ค.ศ. (เช่น "ตุลาคม 2026")
- แสดง "เลขที่ N" ของ comment จาก `comments.seat_no` ที่เก็บไว้ตอนโพสต์ (ไม่ join) เพื่อให้ข้อมูลเก่าไม่เปลี่ยนเมื่อปีหน้าเลขที่ถูกจัดใหม่
- **ลิงก์:** ข้อความของ entry (สิ่งที่เรียน, โจทย์การบ้าน) และ comment วางลิงก์ได้ ไม่ต้องมีฟิลด์แยก ฝั่งแสดงผลแปลง URL `http(s)` เป็นปุ่ม (🎓 Google Classroom, 🎨 Canva, ▶ YouTube, 📄 Google Docs/Drive, 🔗 โดเมนอื่น) เปิดแท็บใหม่ด้วย `rel="noopener noreferrer nofollow"` ใช้เฉพาะ `http`/`https` และ escape ข้อความก่อนแปลงเสมอ ไม่ฝังเนื้อหาจากลิงก์ (ไม่ใช้ iframe)
- ใช้ soft delete ผ่าน `hidden` เพื่อกู้คืนได้

## 9. เส้นทาง (routes)

```
/                      รายการห้อง (redirect ถ้ามีห้องเดียว)
/c/{slug}              หน้าหลัก (หน้าเดียวแบบระบบเดิม): ปุ่มบันทึก + เลือกวัน + สิ่งที่เรียน + การบ้านที่ต้องส่ง + ข้อความ
/c/{slug}/manage       class admin: วิชา, นักเรียน, ตั้งค่า (ดูหัวข้อ 9.2)
/admin                 super admin: สร้าง/ปิดห้อง ตั้งรหัสแอดมินห้อง
```

- ไม่มีหน้า archive แยก: "ดูย้อนหลัง" คือการเลือกวันในหน้าหลัก (เหมือนระบบเดิม)
- `/admin/*` ป้องกันด้วย Cloudflare Access แล้วตรวจ email กับ `SUPER_ADMINS` ใน Worker อีกชั้น
- API เขียนของ class admin ตรวจ cookie ที่เซ็นแล้ว (ชื่อ + `pin_version`) ทุกครั้ง

**ฟอร์มบันทึก (ขยายใต้ปุ่มเหลือง)** ฟิลด์: วันที่เรียน (default วันนี้) → วิชา (เลือกจากวิชาของห้อง) → สิ่งที่เรียนวันนี้ → การบ้าน (ไม่มี/มี) ถ้า "มี" จึงโชว์ โจทย์การบ้าน + วันที่ส่ง (default วันถัดไป) + แนบรูปได้ (ไม่เกิน 3) → [บันทึกข้อมูล]

**การระบุตัวตนครั้งแรก:** กดปุ่มเหลืองบนอุปกรณ์ที่ยังไม่เคยระบุ จะขึ้นกล่องในหน้าเดิมให้กรอก "ชื่อผู้บันทึก" + "รหัสแอดมินห้อง" ครั้งเดียว แล้วจำใน cookie (~90 วัน) หลังจากนั้นกดแล้วเห็นฟอร์มทันที และแสดง "บันทึกโดย: {ชื่อ} (ไม่ใช่ฉัน?)" ไว้ในฟอร์ม

**รูปและความคิดเห็นในการ์ด:** การ์ดแสดงรูปที่แนบ (thumbnail กดขยาย) และปุ่ม `💬 N ความคิดเห็น ▸ อ่าน / เขียน` กดแล้วการ์ดขยายแสดงความคิดเห็น (เลขที่ N · เวลา · ข้อความ · รูป) พร้อมฟอร์มเขียน: รหัส (ช่อง password กรอกครั้งเดียว จำใน cookie) + ข้อความ/ลิงก์ + แนบรูปได้ไม่เกิน 2 รูป (ย่อฝั่ง client เหมือนรูปใน entry) ต้องมีข้อความหรือรูปอย่างน้อยหนึ่งอย่าง

## 9.2 หน้าจัดการห้อง `/c/{slug}/manage`

สำหรับ class admin เท่านั้น (ต้องระบุตัวตนด้วยชื่อ + รหัสแอดมินห้อง ถ้าเครื่องนี้เคยกรอกแล้วเข้าได้ทันที) Mobile first แบ่งเป็น 3 แท็บ ต้นแบบอยู่ที่ `docs/mockups/manage.html`

**📚 วิชา**
- รายการวิชาของห้อง (รหัสวิชา + ชื่อ + จำนวนบันทึก) เรียงตามลำดับที่แสดงในช่อง "เลือกวิชา"
- ปุ่มต่อวิชา: ▲ ▼ เลื่อนลำดับ (ไม่ใช้ลากวาง เพราะใช้ยากบนมือถือ), ✎ แก้ไขในแถวเดิม, 🙈/👁 ซ่อน/แสดง, 🗑 ลบ
- ลบได้เฉพาะวิชาที่ยังไม่มีบันทึก ถ้ามีแล้วปุ่มลบถูกปิดและให้ "ซ่อน" แทน (วิชาที่ซ่อนไม่ขึ้นในช่องเลือกวิชา แต่การ์ดเก่ายังเห็นครบ)
- เพิ่มวิชา: รหัสวิชา + ชื่อวิชา + **ผู้สอน (ไม่ใส่ก็ได้)** รหัสวิชาห้ามซ้ำในห้อง ผู้สอนที่ใส่ไว้จะแสดงเล็กๆ ที่การ์ดในหน้าหลัก (แก้ชื่อผู้สอนมีผลกับการ์ดเก่าของวิชานั้นด้วย ถ้าปีหน้าผู้สอนเปลี่ยน ให้ซ่อนวิชาเดิมแล้วเพิ่มวิชาใหม่)
- การลบกดสองครั้ง (กดแล้วปุ่มเปลี่ยนเป็น "ยืนยันลบ?" ภายใน 3 วินาที) ไม่ใช้กล่องยืนยันของเบราว์เซอร์

**🧒 นักเรียน**
- สรุป ทั้งหมด / ใช้งาน / ซ่อน, ช่องค้นหาด้วยเลขที่หรือรหัส, รายการเรียงตามเลขที่
- ปุ่มต่อคน: ✎ แก้เลขที่/รหัส, 🙈/👁 ซ่อน/แสดง (ซ่อน = ย้ายออก รหัสนี้โพสต์ไม่ได้อีก แต่ความคิดเห็นเก่ายังอยู่) ไม่มีการลบนักเรียนถาวร
- เพิ่มนักเรียนด้วยกล่องเดียว: วางได้หลายบรรทัด บรรทัดละคน รูปแบบ `เลขที่ รหัส` (คั่นด้วยเว้นวรรค จุลภาค หรือแท็บ จึงวางจาก Excel/Google Sheets ได้) หรือพิมพ์เฉพาะรหัส ระบบเรียงเลขที่ต่อให้ มีตัวอย่างผล (✓/✗ พร้อมเหตุผล) ก่อนกดเพิ่ม และเพิ่มเฉพาะบรรทัดที่ถูกต้อง
- กติกา: เลขที่ 1–99 ไม่ซ้ำในหมู่นักเรียนที่ใช้งาน, รหัสเป็นตัวอักษรหรือตัวเลข 3–20 ตัว ไม่ซ้ำทั้งห้อง (รวมคนที่ซ่อนอยู่ ถ้าซ้ำกับคนที่ซ่อนอยู่ให้กด "แสดง" แทน)
- แก้เลขที่ได้โดยไม่กระทบของเก่า: ความคิดเห็นเก็บ `seat_no` ตอนโพสต์ไว้ ปีหน้าจัดเลขที่ใหม่ได้ ข้อความเก่ายังแสดงเลขที่เดิม
- รายชื่อใช้ต่อข้ามปีได้ ขึ้นปีใหม่ซ่อนคนที่ย้ายออกและเพิ่มคนใหม่

**⚙ ตั้งค่า**
- **ภาคเรียน:** รายการภาคเรียนเรียงใหม่สุดก่อน แต่ละอันมี ชื่อภาคเรียน · ชื่อห้องในภาคเรียนนั้น · ช่วงวันที่ · ปุ่ม ✎ แก้ไข และ "ตั้งเป็นปัจจุบัน" ไม่มีปุ่มลบ (ภาคเรียนเก่าต้องอยู่เพื่อดูย้อนหลัง)
  - สร้างภาคเรียนใหม่: ชื่อ, ชื่อห้องในภาคเรียนนี้ (เสนอค่าเดิมให้แก้), วันเปิด/ปิดเทอม (เสนอวันเปิด = วันถัดจากภาคเรียนล่าสุด), ติ๊ก "ตั้งเป็นภาคเรียนปัจจุบันเลย"
  - ตรวจ: วันปิดไม่ก่อนวันเปิด, ช่วงวันที่ห้ามทับภาคเรียนอื่น, ชื่อภาคเรียนไม่ซ้ำ
  - มีกล่อง "ขึ้นปีการศึกษาใหม่ ทำตามนี้" 3 ขั้น: สร้างภาคเรียน+เปลี่ยนชื่อห้อง → จัดนักเรียน → จัดวิชา/ผู้สอน
  - บันทึกใหม่ต้องมีวันที่อยู่ในภาคเรียนปัจจุบัน (ฟอร์มบนหน้าหลักตรวจและจำกัดวันที่ให้)
- (ชื่อห้องไม่ได้ตั้งที่นี่แยกต่างหาก อยู่ในแต่ละภาคเรียน)
- เปลี่ยนรหัสแอดมินห้อง: รหัสใหม่ตัวเลข 4–8 หลัก + พิมพ์ซ้ำ เมื่อเปลี่ยน `pin_version` เพิ่มขึ้น ทำให้แอดมินเครื่องอื่นต้องกรอกรหัสใหม่ (เครื่องที่เปลี่ยนไม่ต้องกรอกใหม่)
- ที่ซ่อนไว้: รายการการ์ดและความคิดเห็นที่ถูกซ่อน (`hidden = 1`) พร้อมปุ่ม "กู้คืน" ผู้ซ่อนและเหตุผลเก็บไว้ใน log

**หมายเหตุสำหรับระบบจริง**
- ทุก API ของหน้านี้ตรวจ cookie แอดมินและ `pin_version` ฝั่ง server ทุกครั้ง ไม่เชื่อสถานะจากหน้าเว็บ
- โครงสร้างข้อมูลที่เกี่ยวข้องอยู่ในหัวข้อ 8 (`terms`, `subjects.teacher`, `hidden_by/hidden_at`, `comments.seat_no`)
- ผู้ดูแลระบบ (super admin) มีหน้า `/admin` แยก ยังไม่ได้ออกแบบ (สร้าง/ปิดห้อง ตั้งรหัสแอดมินห้องเริ่มต้น)

## 9.3 การใช้งานข้ามหลายปี

- **ห้องเดียวใช้ต่อได้นาน:** `slug`/URL คงที่ ปีใหม่แค่สร้างภาคเรียนใหม่ ไม่ต้องสร้างห้องใหม่ และไม่ต้องย้ายข้อมูล
- **สิ่งที่เปลี่ยนตามปีอยู่กับภาคเรียน:** ชื่อห้อง (ป.5/1 → ป.6/1) ช่วงวันที่ รายชื่อและวิชาที่ใช้งานจัดการด้วยการซ่อน/เพิ่ม ข้อมูลเก่าไม่ถูกแก้
- **ข้อมูลเก่าไม่ปนหน้าแรก** แต่ยังดูได้จากตัวเลือกภาคเรียน
- **ปริมาณข้อมูล (ประมาณ):** ห้อง 30 คน ~1,000–1,500 การ์ดต่อปี ข้อความล้วนเล็กมากเมื่อเทียบกับโควตา D1 ฟรี ส่วนรูปที่ย่อแล้ว ~300KB ต่อรูป ถ้ามีราว 1,500 รูปต่อปี ≈ 450MB ต่อปี R2 ฟรี 10GB รองรับหลายปี (ตรวจโควตาจริงก่อนใช้งาน)
- **เมื่อพื้นที่รูปใกล้เต็ม (ฟีเจอร์อนาคต):** แสดงพื้นที่ที่ใช้ในหน้าตั้งค่า และให้ class admin "ลบรูปของภาคเรียนที่ผ่านมา" โดยเก็บข้อความไว้
- **Backup:** export D1 เป็นระยะ ตามหัวข้อ 4.3 เมื่อใช้หลายปี ควร backup ก่อนสิ้นภาคเรียนทุกครั้ง
